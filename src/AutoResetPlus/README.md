# AutoResetPlus

整链重置插件（UTSL 多世界版）。

## 为什么不能照搬原插件

原版 AutoResetPlus 是 **TShock 单世界**重置（进程内 WorldGen.CreateNewWorld → WorldFile.LoadWorld）。
本服务器的多个世界是**同一张大地图切出来的多片**，各重置各的会让接缝立刻断裂，
所以必须**整链重置**：生成一张新源地图 → 重新切分 → 替换所有切片 → 重启。

## 指令

| 指令 | 说明 |
|:--|:--|
| /reset | 整链重置全部世界 |
| /resetdata | 重置数据 |
| /rs info | 查看预设/状态 |
| /rs name <名称> | 设置重置后世界名 |
| /rs seed <种子> | 设置下次种子 |

## 工作流程

**阶段 1（插件进程内）**
广播倒计时 → 执行「重置前指令」→ 踢人 → 把 UTSL 启动列表切成「只留源地图」
→ 写 pending-reset.json → 启动重启脚本 → 退出进程

**阶段 2（下次启动自动续跑）**
等源地图生成 → 主动触发保存 → 写 EdgeStitch 配置与启动列表
→ 生成 PowerShell 脚本并退出（**关键：切分移出服务器进程，峰值内存 2x → 1x**）
→ 脚本：切分 → 部署切片 → 执行「替换文件/重置后指令/SQL/抽下次种子」→ 启动服务器

## 配置

config/AutoResetPlus/MultiWorld.json

| 字段 | 说明 |
|:--|:--|
| 片宽 | 目标片宽，**必须是 200 的整数倍**（建议 4200） |
| 切片数 | 世界数量（2~6 均验证过算法） |
| 重叠量 | 相邻片重叠格数，需满足 3×重叠×(份数−1) 是 200 的倍数 |
| 源地图宽度 | 由片宽/份数/重叠自动推导，一般不用手填 |
| 世界链 | 世界顺序（与 EdgeStitch 一致） |
| 下次重置种子 / 重置后世界名 / 随机种子配置 | 种子相关 |
| 替换文件 / 重置前指令 / 重置后指令 / 重置后SQL命令 | 钩子 |

## 几何自检（内置）

实测血泪：片宽或源地图宽不是 200 的整数倍会导致客户端小地图偏移、切分出错。
插件会在重置前自动校验并修正到最近的合法值，同时打 Warning：

~~~
[AutoResetPlus] 片宽 4000 不是 200 的整数倍（会导致小地图偏移），已自动改为 4000...
[AutoResetPlus] 重叠量 28 会让源地图宽不是 200 的整数倍（区块残缺），已自动改为 100
~~~

## 各切片数对应参数（片宽 4200）

| 切片数 | 重叠量需为 | 建议 | 源地图宽 | 高度 | 图格 |
|:--|:--|:--|:--|:--|:--|
| 2 | 200 的倍数 | 200 | 7800 | 2400 | 1872万 |
| 3 | 100 的倍数 | 100 | 12000 | 2400 | 2880万 |
| 4 | 200 的倍数 | 200 | 15000 | 1800 | 2700万 |
| 5 | 50 的倍数 | 100 | 19800 | 1200 | 2376万 |
| 6 | 40 的倍数 | 120 | 23400 | 1200 | 2808万 |

## 依赖

- UTSL（UnifierTSL）
- EdgeStitch（读取/写入其配置以保持世界链一致）
- UTSLStitchTool（配套命令行切分工具）
