# MiniGameCore 小游戏核心
- **作者**: 星梦
- **版本**: v0.1.0（契约 v1）
- **类型**: **模块本体**（`[assembly: CoreModule]`）——小游戏玩法（如 Parkour）以子插件形式挂在它下面

## 功能概述
- **房间状态机**：`Idle → Preparing（倒计时）→ Running → Settling → Resetting → Idle`，房间可复用，世界不必反复重建
- **原子占房**：同一张图被多人同时请求时，容量判定与占房在同一把锁里完成，不会把两个人塞进单人房
- **倒计时与结算**：倒计时结束才开跑；结算幂等（完赛/超时/房间空/时限多路径只结算一次）
- **结算线程安全**：结算在房间世界线程执行，避免与判定逻辑并发改状态
- **回收**：空闲房间按 `房间_空置销毁秒` 自动回收（含世界）；玩家掉线、房间无活人时会自动结算
- **排行榜（存储层）**：统一表结构 + `ILeaderboardStore`（写入/查询/缓存/清榜），排序键与方向由玩法传入 —— **机制在核心、语义在玩法**
- 与 `VirtualWorldCore` 通过契约发现（契约版本不匹配会明确禁用并打日志），不绑定具体类型名

## 指令
| 语法 | 权限 | 说明 |
|------|:----:|------|
| `/mg rooms` | `minigame.admin` | 列出房间（玩法/地图/模式/状态/人数/tick）与已登记玩法 |
| `/mg reload` | `minigame.admin` | 热重载 `settings.json`（解析失败不会覆盖原文件） |

> 玩家侧指令由各玩法提供（跑酷为 `/pk`）。

## 配置
配置文件路径：`config/MiniGameCore/settings.json`

```json
{
  "房间_最多同时存在": 8,
  "等候厅_空置卸载秒": 5,
  "等候厅_就绪超时秒": 120,
  "房间_空置销毁秒": 300,
  "宽限_默认秒": 60,
  "排行榜_赛季": "s1"
}
```

## 配置说明
| 键 | 默认 | 说明 |
|------|:----:|------|
| `房间_最多同时存在` | 8 | 同时存在的房间上限（0 = 不限）；超限会被拒绝并提示 |
| `等候厅_空置卸载秒` | 5 | 等候厅没人多久后卸载（多人模式用，P2） |
| `等候厅_就绪超时秒` | 120 | 等候厅到点未满员则按现有人数开局（P2） |
| `房间_空置销毁秒` | 300 | 房间空置多久后回收（含假世界）；0 = 不回收 |
| `宽限_默认秒` | 60 | 首名完赛后的宽限（可被地图覆盖） |
| `排行榜_赛季` | s1 | 赛季标识，便于清榜/开新赛季 |

## 说明
- **部署布局**：`plugins/MiniGameCore/{MiniGameCore.dll, Parkour.dll, lib/MiniGameCore.Abstractions.dll}`
  契约程序集必须与核心同目录或在 `lib/`，且**不要**在 plugins 根目录留同名副本（根目录按文件名去重会覆盖子目录，导致加载旧版本）
- **契约版本**：`MiniGameApi.Version`，玩法发现时校验；不匹配会禁用玩法并在日志说明
- 同一张图的地图世界尺寸必须与玩家所在世界一致（1.4.5.8 的无缝转移硬限制）
- 房间复用：新一局开始时玩法需自行清理本局状态（跑酷在 `OnRoundStart` 里清）——契约层的钩子保证每局调用一次
